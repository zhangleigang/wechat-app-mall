# HDFS读写流程详解

## 【问题】

HDFS的读写流程是怎样的？

## 【答案】

### 3-5分钟快速总结

**HDFS写入流程（管道式写入）：**
1. 客户端向NameNode请求创建文件
2. NameNode检查权限，返回DataNode列表（通常3个）
3. 客户端与DataNode建立**写入管道**（如DN1→DN2→DN3）
4. 数据分包传输，每个包沿管道顺序传递
5. 各DataNode确认写入成功后，反向发送ACK确认
6. 完成后通知NameNode更新元数据

**HDFS读取流程（就近读取）：**
1. 客户端向NameNode请求文件信息
2. NameNode返回数据块位置列表（按距离排序）
3. 客户端选择**最近的DataNode**直接连接读取
4. 如果DataNode故障，自动切换到其他副本
5. 按顺序读取所有数据块，组装成完整文件

**核心特点**：写入采用管道复制，读取采用就近访问，NameNode只提供元数据，不参与实际数据传输。

### 详细流程解析

#### 一、HDFS写入流程

HDFS的写入采用**管道式复制**机制，确保数据可靠性的同时优化网络带宽使用。

**第1步：文件创建请求**
```
客户端 → NameNode: create("/user/data/file.txt")
```
- 客户端调用`create()`方法向NameNode发起请求
- NameNode执行权限检查、文件是否存在等验证
- 检查通过后，NameNode在元数据中创建文件记录
- 返回`FSDataOutputStream`给客户端

**第2步：数据块分配**
```
客户端 → NameNode: 请求分配数据块
NameNode → 客户端: 返回DataNode列表[DN1, DN2, DN3]
```
- 当缓冲区达到一个数据块大小（128MB）时触发
- NameNode根据副本策略选择DataNode：
  - 第一个副本：客户端本地或同机架
  - 第二个副本：不同机架的随机节点
  - 第三个副本：与第二个副本同机架的不同节点

**第3步：建立写入管道**
```
客户端 → DN1 → DN2 → DN3
```
- 客户端与第一个DataNode建立连接
- DN1与DN2建立连接，DN2与DN3建立连接
- 形成数据传输管道：客户端→DN1→DN2→DN3

**第4步：数据包传输**
```
数据包流向：客户端 → DN1 → DN2 → DN3
确认流向：DN3 → DN2 → DN1 → 客户端
```
- 客户端将数据切分成64KB的数据包
- 第一个数据包发送给DN1
- DN1接收后立即转发给DN2，同时写入本地磁盘
- DN2接收后立即转发给DN3，同时写入本地磁盘
- DN3接收后写入本地磁盘，发送ACK给DN2
- ACK沿管道反向传递：DN3→DN2→DN1→客户端

**第5步：管道容错处理**

如果管道中某个DataNode故障：
- 客户端检测到连接中断
- 从管道中移除故障节点
- 向NameNode请求新的DataNode
- 重建管道继续传输
- 故障节点恢复后，NameNode会清理其不完整数据

**第6步：文件关闭**
```
客户端 → NameNode: close()
```
- 刷新所有剩余数据包
- 通知NameNode文件写入完成
- NameNode提交元数据更改

#### 二、HDFS读取流程

HDFS的读取采用**就近访问**策略，最大化读取性能。

**第1步：文件打开请求**
```
客户端 → NameNode: open("/user/data/file.txt")
```
- 客户端调用`open()`方法
- NameNode验证文件存在性和访问权限

**第2步：获取数据块位置**
```
NameNode → 客户端: 返回数据块位置信息
[
  Block1: [DN1, DN3, DN5] (按距离排序)
  Block2: [DN2, DN4, DN6] (按距离排序)
  ...
]
```
- NameNode返回文件的数据块列表
- 每个块包含所有副本的DataNode地址
- 地址按网络拓扑距离排序（最近的在前）

**第3步：创建输入流**
```
客户端创建FSDataInputStream
```
- 客户端获得数据块信息后创建输入流
- 准备开始数据读取

**第4步：读取数据块**
```
客户端 → 最近的DataNode: 读取Block1
DataNode → 客户端: 数据流传输
```
- 客户端选择第一个数据块的最近DataNode
- 建立直接连接开始数据传输
- 数据以流的形式传输（通常64KB包）

**第5步：容错切换**

如果当前DataNode故障：
```
客户端检测到连接错误
↓
自动切换到下一个最近的DataNode
↓
继续读取数据
```
- 客户端自动检测连接或数据校验错误
- 立即切换到该块的下一个副本
- 对用户透明，无需重新发起请求

**第6步：顺序读取后续块**
```
Block1读取完成 → 关闭连接
↓
向NameNode请求下一批数据块位置
↓
连接Block2的最近DataNode
↓
重复读取过程
```

**第7步：关闭输入流**
```
客户端调用close()方法
```

#### 三、核心设计优势

**写入优势：**
- **管道复制**：节省客户端上传带宽，数据只需上传一次
- **流水线操作**：数据包可以并行传输，提高效率
- **机架感知**：优化副本放置，平衡可靠性和性能
- **自动容错**：管道故障时自动重建，保证写入成功

**读取优势：**
- **就近访问**：优先从最近的DataNode读取，减少网络延迟
- **负载均衡**：多个副本分散读取压力
- **自动故障转移**：DataNode故障时无缝切换
- **块级并行**：大文件可以并行读取多个块

**整体优势：**
- **NameNode不参与数据传输**：避免成为性能瓶颈
- **数据本地性**：计算任务优先调度到数据所在节点
- **高吞吐量**：优化大文件的顺序读写
- **容错性强**：多重容错机制保证数据安全
