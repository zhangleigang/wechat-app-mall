# HDFS架构原理详解

## 【问题】

HDFS的架构是什么样的？

## 【答案】

### 3-5分钟快速总结

HDFS采用**主从（Master-Slave）架构**，主要包含三个核心组件：

1. **NameNode（主节点）** - 管理文件系统元数据，不存储实际数据
2. **DataNode（从节点）** - 存储实际数据块，定期向NameNode汇报
3. **Secondary NameNode（辅助节点）** - 帮助NameNode合并元数据，不是热备

**核心工作原理**：
- 文件被切分成固定大小的数据块（默认128MB）
- 每个数据块默认复制3份，分布在不同DataNode上
- NameNode记录文件与数据块的映射关系
- 客户端读写时先联系NameNode获取位置信息，再直接与DataNode交互

这种设计实现了高容错性、高吞吐量和横向扩展能力。

### 详细架构解析

#### 1. NameNode（主节点/大脑）

NameNode是HDFS的核心管理者，负责：

**主要职责：**
- **管理文件系统元数据**：记录文件系统的目录树结构、文件与数据块的映射关系
- **协调客户端访问**：处理客户端的读写请求，提供数据块位置信息
- **管理数据块复制**：监控DataNode状态，维护副本因子
- **处理命名空间操作**：文件的创建、删除、重命名等操作

**元数据存储：**
- **FsImage**：文件系统元数据的完整快照
- **EditLog**：记录所有修改操作的日志文件
- 元数据全部加载到内存中，实现快速访问

**关键特点：**
- 单点故障风险（可通过HA解决）
- 内存瓶颈（元数据量受内存限制）
- 不存储实际数据，只管理元数据

#### 2. DataNode（从节点/劳动力）

DataNode是HDFS的工作节点，负责：

**主要职责：**
- **存储数据块**：将HDFS数据块存储在本地磁盘
- **服务读写请求**：响应客户端的数据读写操作
- **执行数据块操作**：根据NameNode指令进行数据块的创建、删除、复制
- **定期汇报状态**：
  - 心跳（每3秒）：告知NameNode自己的健康状态
  - 块报告（定期）：汇报存储的所有数据块列表

**关键特点：**
- 无状态设计，只负责存储和管理数据块
- 支持廉价商用硬件，通过副本机制保证可靠性
- 可以动态添加或移除节点

#### 3. Secondary NameNode（辅助节点）

**重要提醒**：Secondary NameNode不是NameNode的热备！

**主要作用：**
- 定期合并FsImage和EditLog，生成新的FsImage
- 防止EditLog文件过大，加快NameNode重启速度
- 减轻NameNode的合并负担

**工作流程：**
1. 定期联系NameNode，触发检查点操作
2. 下载FsImage和EditLog文件
3. 在本地合并生成新的FsImage
4. 将新FsImage发回给NameNode

#### 4. HDFS高可用架构（现代版本）

为解决单点故障问题，HDFS 2.x引入了HA架构：

- **Active NameNode**：处理所有客户端请求
- **Standby NameNode**：热备状态，实时同步元数据
- **共享存储（JournalNodes）**：Active NameNode写入EditLog，Standby NameNode读取同步
- **ZKFC**：基于ZooKeeper的故障转移控制器，自动切换

#### 5. 数据读写流程

**写入流程：**
1. 客户端向NameNode请求创建文件
2. NameNode检查权限，返回DataNode列表
3. 客户端与DataNode建立写入管道
4. 数据以管道方式在DataNode间传输
5. 完成后通知NameNode更新元数据

**读取流程：**
1. 客户端向NameNode请求文件信息
2. NameNode返回数据块位置列表
3. 客户端直接连接最近的DataNode读取数据
4. 如果DataNode故障，自动切换到其他副本

#### 6. 核心设计优势

**高容错性：**
- 数据块多副本机制
- DataNode故障自动检测和恢复
- 副本自动重新平衡

**高吞吐量：**
- 客户端直接与DataNode交互
- 并行读写多个数据块
- 流式数据访问优化

**横向扩展：**
- 可以轻松添加DataNode节点
- 存储容量和计算能力线性增长
- 支持PB级数据存储
