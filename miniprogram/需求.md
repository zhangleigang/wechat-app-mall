# 楼盘团购小程序开发计划 (MVP版本)

## 1. 摘要 (Summary)

根据《楼盘团购需求文档.md》，为即将交付的楼盘业主开发一款“单页面”团购拼团应用（MVP版本）。 该功能采用全栈开发：

- **后端**：在当前 `ai-interview` 项目（Node.js + Express + MySQL）中新增团购 API 及数据库表。京东商品解析功能暂使用 Mock 数据替代。
- **前端**：在相邻的 `wechat-app-mall` 原生小程序项目中新增页面及组件，利用其已安装的 Vant Weapp UI 库实现底部的发布浮层（ActionSheet/Popup）、详情展开等单页交互。

## 2. 现状分析 (Current State Analysis)

- **后端架构**：入口 `server.js`，包含 MySQL 连接池及 JWT 鉴权中间件。现有的路由挂载模式为 `app.use('/api/...', ...Routes)`。
- **前端架构**：`wechat-app-mall/app.json` 中配置了多个 Vant Weapp 组件（如 `van-search`, `van-tab`, `van-action-sheet`, `van-card` 等），非常适合快速搭建极简的单页布局。

## 3. 拟定变更 (Proposed Changes)

### 3.1 数据库结构 (MySQL)

修改文件：`database/init.sql` (需手动同步到开发库) 新增两张精简版数据表：

1. **`group_products`**（团购商品表）
   - 字段：`id` (主键), `jd_url` (商品链接), `jd_sku_id` (京东SKU，用于跳转京东小程序), `title` (商品名称), `image` (主图), `category` (分类), `jd_price` (京东当前价), `room_no` (发布者房号，如"4-2002-C"), `openid` (发布者), `created_at` (发布时间)。
2. **`group_intentions`**（团购意向表）
   - 字段：`id` (主键), `product_id` (商品外键), `openid` (参与者), `room_no` (参与者房号，如"4-2002-C"), `created_at`。
   - 联合唯一索引：`(product_id, openid)`，确保同一用户对同一商品只能登记一次。

### 3.2 后端 API 开发

新增文件：`src/routes/group-buy.js` 修改文件：`server.js` (注册路由 `app.use('/api/group-buy', groupBuyRoutes)`)

接口列表：

1. `POST /api/group-buy/parse`
   - 功能：解析京东链接 (MVP阶段：正则提取 URL 中的 skuId，其余字段返回固定的 Mock 数据如“测试冰箱”、“默认图片”、“随机价格”)。
2. `POST /api/group-buy/products`
   - 功能：发布新商品。插入 `group_products`，并默认将发布者本人作为第一个意向用户插入 `group_intentions`。
   - 鉴权：从请求体获取 `openid` 即可，不使用 `authMiddleware`（适配当前小程序前端的无 Token 直接传 OpenID 模式）。
3. `GET /api/group-buy/products`
   - 功能：获取商品列表（支持 `category` 筛选，支持 `sort=time|hot` 排序）。
4. `GET /api/group-buy/products/:id`
   - 功能：获取商品详情，包含 `intentions`（所有参与该商品意向的邻居房号列表）。
5. `POST /api/group-buy/products/:id/intentions`
   - 功能：我要登记意向。插入 `group_intentions`，并更新 `group_products.intention_count`。
   - 鉴权：从请求体获取 `openid` 即可，不使用 `authMiddleware`。

### 3.3 小程序前端开发

项目路径：`/Users/flow/Desktop/LLM/wechat-app-mall` 修改文件：`app.json` (注册新页面) 新增页面与组件：

1. **主页面** `pages/group-buy/index`
   - 包含：顶部搜索框（`van-search`），分类 Tabs（`van-tabs`），滚动商品列表。
   - 底部固定按钮：“🏠 我要发布”。
   - **页面标题**：顶部导航栏名称定为 **“熙府随心选”**。
   - **独立分享页设计**：该页面无需在小程序的底部导航栏（TabBar）新增入口，作为独立页面使用，开启 `onShareAppMessage`，由业务员直接分享给业主打开。
2. **发布浮层组件** (内部实现或使用 `van-popup` / `van-action-sheet`)
   - 包含四步流程：粘贴链接 -> 解析加载 -> 确认信息（填写房号） -> 提交。
   - **房号输入设计**：为了确保“4-2002-C”这种格式的准确性，前端在发布和登记意向时，将提供三个分离的输入框：\[栋/单元] - \[房号] - \[户型]，用户填完后前端自动拼接成统一格式提交。
3. **商品卡片与详情展开**
   - 默认展示商品摘要，点击后利用条件渲染在下方展示大图、房号列表及“我要登记”按钮。
   - **数据汇总功能（新增）**：在详情区的意向邻居列表旁，增加一个“一键复制”按钮。业务员或发布者点击后，可将所有登记了意向的房号名单（如"5-2003, 3-1801"）直接复制到手机剪贴板，极大方便业务员在微信群里接龙或汇总。

### 3.4 链接解析与京东小程序跳转

- **京东商品登记解析（核心）**：
  - **现状痛点**：用户复制的通常是京东App的分享文案，包含短链或乱码。若真写爬虫去解短链，MVP成本过高。
  - **解决方案（正则盲提）**：后端 `POST /api/group-buy/parse` 接口接收一段文本，直接利用正则表达式提取连续的 8-12 位数字（`\d{8,12}`）作为 **SKU ID**。提取成功后，商品名称和价格暂用固定的 Mock 数据返回；如果提取失败，则报错提示用户“未找到商品编号，请重试”。
- **去购买跳转（核心）**：
  - **前端实现**：商品详情中的“去京东购买”按钮点击时，前端调用 `wx.navigateToMiniProgram`。
  - **参数配置**：
    - `appId`: `wx91d27dbf599dff74` (京东购物官方小程序)。
    - `path`: `/pages/item/detail/detail?sku=${jd_sku_id}`。
    - 这样只要用户在登记时文案里有正确的数字编号，其他人点击就能**真正**打开京东小程序并跳到对应商品详情页，完美跑通核心业务流。

## 4. 假设与决策 (Assumptions & Decisions)

- **身份标识**：后端 API 通过请求参数（如 `req.body.openid`）识别用户，不强制依赖 JWT（`authMiddleware`），从而兼容前端目前的 `apifm-wxapi` 登录机制。房号 (`room_no`) 由用户在发布/登记时手动填写，拼接后仅作页面展示使用。
- **解析方案**：采用 Mock 方案，正则表达式 `/jd\.com.*[/\?](\d+)/` 或直接提取数字作为 `skuId`，标题、图片、价格返回固定测试值，以便快速跑通主流程。
- **单页交互**：小程序前端不进行页面跳转，详情展开及发布表单均通过数据驱动在当前页内通过隐藏/显示及弹出层实现。

## 5. 验证步骤 (Verification Steps)

1. **后端 API 验证**：
   - 使用 Postman 或 curl 请求 `/api/group-buy/parse` 测试 Mock 解析是否成功。
   - 请求发布商品、列表查询接口，检查 MySQL 数据是否正确写入并返回。
   - 测试重复登记意向，验证联合唯一索引是否正确拦截并返回相应业务错误。
2. **前端交互验证**：
   - 编译并在微信开发者工具中预览 `wechat-app-mall`。
   - 测试“发布 -> 弹窗 -> 粘贴链接 -> 提交”完整闭环。
   - 测试点击列表商品能否平滑展开详情，并成功进行“我要登记”。
   - 验证排序切换（按时间/按热度）及分类筛选是否正常。
