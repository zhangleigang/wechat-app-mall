## 一面：数据仓库基础面试

### 面试官背景
美团数据平台部门高级工程师，负责离线数据仓库架构设计，有8年数据仓库经验。

### 技术问题回顾

#### 问题1：请介绍一下数据仓库的分层架构
**我的回答**：我从ODS、DWD、DWS、ADS四层架构开始介绍，详细说明了每层的作用和数据流转过程。
**面试官追问**：为什么要分层？不分层直接从源系统到应用层不行吗？
**反思总结**：这个追问很关键，要从数据复用、开发效率、数据质量等角度回答分层的价值。

#### 问题2：如何设计一个电商订单主题的数据模型？
**我的回答**：我采用了星型模型设计，以订单事实表为中心，关联用户、商品、时间、地域等维度表。
**面试官追问**：如果订单状态会发生变化，如何处理历史数据？
**反思总结**：这里考查的是SCD（缓慢变化维）的处理，需要掌握Type1、Type2、Type3等不同策略。

#### 问题3：Hive中的分区和分桶有什么区别？
**我的回答**：分区是按照某个字段值创建目录结构，分桶是在分区内部按照hash值分散数据。
**面试官追问**：什么场景下使用分桶比较合适？
**反思总结**：分桶主要用于优化join操作和采样查询，需要结合具体业务场景说明。

### 编程题
**题目**：给定一个用户行为日志表，统计每个用户最近30天的活跃天数。

```sql
-- 我的解答
SELECT 
    user_id,
    COUNT(DISTINCT DATE(action_time)) as active_days
FROM user_behavior_log 
WHERE action_time >= DATE_SUB(CURRENT_DATE, 30)
GROUP BY user_id;
```

**面试官追问**：如果数据量很大，如何优化这个查询？
**优化方案**：
1. 按日期分区，只扫描最近30天的分区
2. 使用bitmap或HyperLogLog进行去重计算
3. 预计算每日活跃用户，然后聚合

## 二面：系统设计面试

### 设计题目
设计一个实时数据仓库系统，支持美团外卖业务的实时报表需求。

### 我的设计方案

#### 整体架构
```
数据源 -> Kafka -> Flink -> ClickHouse -> 可视化平台
  |                |
  v                v
离线存储 <- Spark <- HDFS
```

#### 技术选型说明
- **Kafka**：消息队列，保证数据的可靠传输
- **Flink**：实时计算引擎，处理流式数据
- **ClickHouse**：OLAP数据库，支持高并发查询
- **Spark**：离线计算，处理历史数据和复杂分析

#### 关键设计点
1. **数据分层**：实时层(RT)、近实时层(NRT)、离线层(Batch)
2. **数据质量**：实时监控、异常告警、数据校验
3. **性能优化**：预聚合、索引优化、查询缓存

### 面试官追问
**问题1**：如何保证实时数据和离线数据的一致性？
**我的应对**：采用Lambda架构，通过批处理层校正实时层的数据，定期进行数据对账。

**问题2**：ClickHouse如何处理高并发查询？
**我的应对**：通过分布式部署、合理的分区策略、查询优化和缓存机制来提升并发能力。

### 经验总结
系统设计题要从业务需求出发，考虑数据量、并发量、延迟要求等因素，选择合适的技术栈。要能够说清楚每个组件的作用和选择理由。

## 三面：项目经验面试

### 项目深度挖掘
面试官重点询问了我负责的用户画像数据仓库项目。

**项目背景**：为公司营销部门构建用户画像系统，支持精准营销和用户分析。

**技术挑战**：
1. 数据源异构，包括MySQL、MongoDB、日志文件等
2. 用户标签计算复杂，涉及实时和离线两套逻辑
3. 查询性能要求高，需要秒级响应

**解决方案**：
1. 使用DataX进行异构数据源同步
2. 基于Spark开发标签计算引擎，支持规则配置
3. 采用Elasticsearch存储用户画像，优化查询性能

**业务价值**：
- 营销转化率提升25%
- 用户分析效率提升60%
- 支撑了10+个业务场景

### 技术难点攻坚

#### 难点1：实时标签计算性能优化
**问题描述**：用户行为数据量大，实时标签计算延迟高。
**解决过程**：
1. 分析瓶颈，发现是状态存储和窗口计算的问题
2. 优化Flink状态后端，使用RocksDB
3. 调整窗口策略，采用滑动窗口+增量计算
4. 结果：延迟从分钟级降到秒级

#### 难点2：数据质量监控
**问题描述**：数据源不稳定，经常出现数据异常。
**解决过程**：
1. 建立数据质量监控体系
2. 开发自动化数据校验规则
3. 集成告警系统，及时发现问题
4. 结果：数据质量问题发现时间缩短80%

### 团队协作
**协作经验**：与产品、运营、开发等多个团队协作，定期同步需求和进度。
**沟通技巧**：用业务语言解释技术方案，让非技术人员也能理解。
