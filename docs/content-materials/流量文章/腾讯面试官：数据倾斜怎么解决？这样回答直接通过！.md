## 什么是数据倾斜？一个形象的比喻

想象一下公司食堂打饭的场景：
- **正常情况**：4个窗口，每个窗口排队人数差不多，大家都能快速打到饭
- **数据倾斜**：1个窗口排了100人，其他3个窗口只有几个人，那个长队窗口就是"热点"

在大数据处理中：
- **正常情况**：数据均匀分布在各个分区，任务并行执行
- **数据倾斜**：某些分区数据量特别大，成为整个作业的瓶颈

## 数据倾斜的典型表现

### 1. 性能表现
- **作业执行时间异常长**：原本10分钟的任务跑了2小时
- **资源利用率不均**：某些节点CPU 100%，其他节点很空闲
- **频繁的GC和OOM**：热点分区内存不足

### 2. 监控指标异常
```
Task执行时间分布：
- 99%的Task：2分钟完成
- 1%的Task：2小时完成  ← 这就是倾斜！

数据量分布：
- 平均每个分区：100MB
- 最大分区：10GB      ← 100倍差异！
```

### 3. 日志中的典型错误
```
java.lang.OutOfMemoryError: Java heap space
Container killed by YARN for exceeding memory limits
Task attempt failed due to timeout
```

## 数据倾斜的根本原因分析

### 1. 业务数据本身的特点
**热点Key问题**：
- 电商场景：某些爆款商品订单量巨大
- 日志分析：某些IP或用户行为异常频繁
- 社交网络：大V用户的粉丝数据

**示例**：
```sql
-- 用户行为分析，某个用户ID的数据量特别大
SELECT user_id, COUNT(*) as cnt 
FROM user_behavior 
GROUP BY user_id 
ORDER BY cnt DESC;

-- 结果：
-- user_123456: 10,000,000 条记录
-- user_789012: 50,000 条记录
-- ...
```

### 2. 数据处理逻辑设计不当
**分区键选择不合理**：
```scala
// ❌ 错误示例：按日期分区，某些日期数据量巨大
df.repartition($"date")

// ❌ 错误示例：按用户类型分区，VIP用户数据量大
df.repartition($"user_type")
```

### 3. Join操作中的倾斜
**大表Join小表**：
```scala
// 用户表(大) JOIN 订单表(小)
// 如果某些用户的订单特别多，就会产生倾斜
val result = userDF.join(orderDF, "user_id")
```

## 数据倾斜的解决方案

### 方案1：预聚合（最常用）

**适用场景**：GroupBy、ReduceByKey等聚合操作

**核心思想**：在原始Key前加随机前缀，先进行局部聚合，再进行全局聚合

```scala
// ❌ 原始代码：直接聚合，可能产生倾斜
val result = df.groupBy("user_id").agg(sum("amount"))

// ✅ 优化代码：两阶段聚合
import scala.util.Random

// 第一阶段：加随机前缀，局部聚合
val stage1 = df
  .withColumn("random_prefix", lit(Random.nextInt(100)))
  .withColumn("salted_key", concat($"random_prefix", lit("_"), $"user_id"))
  .groupBy("salted_key", "user_id")
  .agg(sum("amount").as("partial_sum"))

// 第二阶段：去掉前缀，全局聚合
val result = stage1
  .groupBy("user_id")
  .agg(sum("partial_sum").as("total_amount"))
```

**效果**：
- 原本1个热点分区 → 100个均匀分区
- 执行时间：2小时 → 15分钟（提升8倍）

### 方案2：广播Join（小表Join大表）

**适用场景**：大表Join小表（小表<200MB）

```scala
// ❌ 原始代码：普通Join可能产生倾斜
val result = bigDF.join(smallDF, "key")

// ✅ 优化代码：广播小表
import org.apache.spark.sql.functions.broadcast

val result = bigDF.join(broadcast(smallDF), "key")
```

**原理**：
- 小表广播到每个Executor
- 避免Shuffle操作
- 消除Join倾斜

### 方案3：拆分热点Key

**适用场景**：少数几个Key数据量特别大

```scala
// 识别热点Key
val hotKeys = df
  .groupBy("key")
  .count()
  .filter($"count" > 1000000)  // 超过100万的认为是热点
  .select("key")
  .collect()
  .map(_.getString(0))
  .toSet

// 分别处理热点和非热点数据
val hotData = df.filter($"key".isin(hotKeys.toSeq: _*))
val normalData = df.filter(!$"key".isin(hotKeys.toSeq: _*))

// 热点数据特殊处理（如加随机前缀）
val processedHotData = hotData
  .withColumn("random_suffix", lit(Random.nextInt(10)))
  .withColumn("new_key", concat($"key", lit("_"), $"random_suffix"))
  // ... 后续处理

// 正常数据正常处理
val processedNormalData = normalData
  // ... 正常处理

// 最后合并结果
val finalResult = processedHotData.union(processedNormalData)
```

### 方案4：增加并行度

**适用场景**：分区数不足导致的倾斜

```scala
// 检查当前分区数
println(s"Current partitions: ${df.rdd.getNumPartitions}")

// 增加分区数
val repartitionedDF = df.repartition(200)  // 根据数据量调整

// 或者使用coalesce（只能减少分区）
val coalescedDF = df.coalesce(50)
```

**分区数设置原则**：
- 每个分区数据量：100MB-200MB
- 分区数 = 数据总量 / 128MB
- 不要超过可用CPU核心数的2-3倍

### 方案5：自定义分区器

**适用场景**：需要精确控制数据分布

```scala
import org.apache.spark.Partitioner

class CustomPartitioner(numPartitions: Int, hotKeys: Set[String]) 
  extends Partitioner {
  
  override def numPartitions: Int = numPartitions
  
  override def getPartition(key: Any): Int = {
    val k = key.toString
    if (hotKeys.contains(k)) {
      // 热点Key分散到多个分区
      (k.hashCode % (numPartitions / 2)).abs
    } else {
      // 普通Key正常分区
      ((k.hashCode % (numPartitions / 2)) + (numPartitions / 2)).abs
    }
  }
}

// 使用自定义分区器
val customPartitioner = new CustomPartitioner(100, hotKeys)
val result = df.rdd.partitionBy(customPartitioner)
```

## 实战案例：电商订单数据倾斜优化

### 背景
- **数据量**：每日10亿订单记录
- **问题**：按商品ID聚合时，爆款商品数据倾斜严重
- **现象**：作业执行时间从30分钟增加到4小时

### 解决过程

**第一步：问题识别**
```scala
// 分析商品ID分布
val productStats = orderDF
  .groupBy("product_id")
  .agg(
    count("*").as("order_count"),
    sum("amount").as("total_amount")
  )
  .orderBy(desc("order_count"))

productStats.show(20)

// 发现：
// product_12345: 50,000,000 订单（爆款手机）
// product_67890: 30,000,000 订单（热门耳机）
// 其他商品：平均 10,000 订单
```

**第二步：解决方案设计**
```scala
// 方案：两阶段聚合 + 热点Key特殊处理
val hotProducts = Set("product_12345", "product_67890")

// 热点商品：加随机前缀，分散到多个分区
val hotOrdersDF = orderDF
  .filter($"product_id".isin(hotProducts.toSeq: _*))
  .withColumn("random_prefix", lit((Math.random() * 50).toInt))
  .withColumn("salted_product_id", 
    concat($"random_prefix", lit("_"), $"product_id"))

// 第一阶段聚合
val hotStage1 = hotOrdersDF
  .groupBy("salted_product_id", "product_id")
  .agg(
    count("*").as("partial_count"),
    sum("amount").as("partial_amount")
  )

// 第二阶段聚合
val hotResult = hotStage1
  .groupBy("product_id")
  .agg(
    sum("partial_count").as("total_orders"),
    sum("partial_amount").as("total_amount")
  )

// 普通商品：正常处理
val normalResult = orderDF
  .filter(!$"product_id".isin(hotProducts.toSeq: _*))
  .groupBy("product_id")
  .agg(
    count("*").as("total_orders"),
    sum("amount").as("total_amount")
  )

// 合并结果
val finalResult = hotResult.union(normalResult)
```

**第三步：效果验证**
- **执行时间**：4小时 → 25分钟（提升9.6倍）
- **资源利用率**：从30% → 85%
- **稳定性**：无OOM错误，GC时间正常

## 面试官最爱问的进阶问题

### Q1：如何在不知道热点Key的情况下解决倾斜？
**标准答案**：
1. **动态采样**：先对数据进行采样，识别热点Key
2. **自适应分区**：根据数据分布动态调整分区策略
3. **多轮处理**：第一轮识别热点，第二轮针对性处理

### Q2：数据倾斜和数据量大有什么区别？
**标准答案**：
- **数据量大**：所有分区数据量都大，可以通过增加资源解决
- **数据倾斜**：部分分区数据量大，增加资源无效，需要重新分布数据

### Q3：如何预防数据倾斜？
**标准答案**：
1. **合理选择分区键**：避免使用倾斜严重的字段
2. **数据预处理**：在ETL阶段就处理热点数据
3. **监控告警**：建立数据倾斜监控机制
4. **代码审查**：在开发阶段就考虑倾斜问题

## 生产环境最佳实践

### 1. 监控体系建设
```scala
// 自动检测数据倾斜的工具函数
def detectSkew(df: DataFrame, keyCol: String, threshold: Double = 0.1): Boolean = {
  val partitionStats = df
    .withColumn("partition_id", spark_partition_id())
    .groupBy("partition_id")
    .count()
    .collect()
  
  val counts = partitionStats.map(_.getLong(1))
  val maxCount = counts.max
  val avgCount = counts.sum.toDouble / counts.length
  
  val skewRatio = maxCount.toDouble / avgCount
  skewRatio > (1 + threshold)
}
```

### 2. 配置优化
```properties
# Spark配置优化
spark.sql.adaptive.enabled=true
spark.sql.adaptive.coalescePartitions.enabled=true
spark.sql.adaptive.skewJoin.enabled=true
spark.sql.adaptive.skewJoin.skewedPartitionThresholdInBytes=256MB

# 内存配置
spark.executor.memory=8g
spark.executor.memoryFraction=0.8
spark.sql.shuffle.partitions=400
```

### 3. 代码规范
```scala
// 建立代码模板
object SkewHandlingUtils {
  
  def handleGroupBySkew[T](df: DataFrame, 
                          keyCol: String, 
                          aggFunc: Column => Column,
                          saltFactor: Int = 100): DataFrame = {
    // 两阶段聚合模板
    val stage1 = df
      .withColumn("salt", (rand() * saltFactor).cast("int"))
      .withColumn("salted_key", concat(col("salt"), lit("_"), col(keyCol)))
      .groupBy("salted_key", keyCol)
      .agg(aggFunc(col("*")).as("partial_result"))
    
    stage1
      .groupBy(keyCol)
      .agg(sum("partial_result").as("final_result"))
  }
}
```
