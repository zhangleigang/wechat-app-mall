# HDFS面试题：HDFS的架构是什么样的？

## 📋 面试问题

**面试官问**：请简述HDFS的架构，包括主要组件和它们的作用。

## ⚡ 快速回答（2-3分钟版本）

### 核心要点
1. **主从架构**：HDFS采用Master-Slave架构，一个NameNode管理多个DataNode
2. **NameNode职责**：管理文件系统元数据，不存储实际数据
3. **DataNode职责**：存储实际数据块，定期向NameNode汇报

### 一句话总结
HDFS是主从架构的分布式文件系统，NameNode管理元数据，DataNode存储数据，通过数据分块和副本机制实现高可靠性。

## 📖 详细解析

### 1. 核心组件说明

**NameNode（主节点）**：
- 管理文件系统命名空间
- 维护文件与数据块的映射关系
- 处理客户端的文件访问请求
- 管理数据块的复制策略

**DataNode（从节点）**：
- 存储实际的数据块
- 定期向NameNode发送心跳和块报告
- 执行数据块的读写操作
- 根据NameNode指令进行数据块复制

**Secondary NameNode（辅助节点）**：
- 定期合并FsImage和EditLog
- 减少NameNode重启时间
- 注意：不是NameNode的热备

### 2. 工作流程

**写入流程**：
1. 客户端向NameNode请求写入文件
2. NameNode检查权限并返回DataNode列表
3. 客户端与DataNode建立写入管道
4. 数据按块写入，每个块默认3个副本

**读取流程**：
1. 客户端向NameNode请求文件位置
2. NameNode返回数据块位置信息
3. 客户端直接从最近的DataNode读取数据

### 3. 高可用设计

**数据可靠性**：
- 数据块多副本存储（默认3副本）
- 跨机架副本放置策略
- 自动故障检测和恢复

**元数据保护**：
- FsImage + EditLog双重保护
- Secondary NameNode定期检查点
- HA模式下的主备切换

## 💡 面试加分项

- **实际经验**：可以提到生产环境中的NameNode内存配置、小文件问题处理
- **深度思考**：说明HDFS适合大文件存储，不适合小文件和随机写入的原因
- **对比分析**：与传统文件系统的区别，与对象存储的对比

### 示例2：Spark性能问题

```markdown
# Spark面试题：groupByKey和reduceByKey有什么区别？

## 📋 面试问题

**面试官问**：Spark中groupByKey和reduceByKey有什么区别？什么时候用哪个？

## ⚡ 快速回答（2-3分钟版本）

### 核心要点
1. **性能差异**：reduceByKey有Map端预聚合，性能更好
2. **数据传输**：groupByKey传输所有数据，reduceByKey只传输聚合结果
3. **使用场景**：能聚合用reduceByKey，需要所有值用groupByKey

### 一句话总结
reduceByKey在Map端预聚合减少数据传输，性能比groupByKey好3-10倍，能用reduceByKey的场景绝不用groupByKey。

## 📖 详细解析

### 1. 工作原理对比

**groupByKey处理流程**：
```
原始数据 → 直接按key分组 → Shuffle传输所有数据 → Reduce端聚合
```

**reduceByKey处理流程**：
```
原始数据 → Map端预聚合 → Shuffle传输聚合结果 → Reduce端最终聚合
```

### 2. 性能差异分析

**Shuffle数据量对比**：
- groupByKey：需要传输所有原始数据
- reduceByKey：只传输预聚合后的结果，数据量大幅减少

**内存使用对比**：
- groupByKey：需要在内存中保存每个key的所有value
- reduceByKey：只需要保存聚合后的中间结果

**实际测试数据**：
```
数据量：1亿条记录
groupByKey：执行时间45分钟，Shuffle 8.5GB
reduceByKey：执行时间12分钟，Shuffle 2.1GB
性能提升：3.75倍
```

### 3. 使用场景区分

**使用reduceByKey的场景**：
```scala
// 统计每个用户的访问次数
userLogs.map(log => (log.userId, 1)).reduceByKey(_ + _)

// 计算每个商品的总销售额
orders.map(order => (order.productId, order.amount)).reduceByKey(_ + _)
```

**必须使用groupByKey的场景**：
```scala
// 获取每个用户的所有访问记录（需要保留原始数据）
userLogs.map(log => (log.userId, log)).groupByKey()

// 计算每个用户访问时间的中位数（非结合性操作）
userLogs.map(log => (log.userId, log.timestamp))
        .groupByKey()
        .mapValues(times => calculateMedian(times.toSeq))
```

- **深度思考**：说明Map端预聚合的原理，以及为什么能大幅提升性能
- **对比分析**：可以提到combineByKey作为更灵活的选择
